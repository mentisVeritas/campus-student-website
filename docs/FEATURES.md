# Функциональность CSW — подробное описание

Документ описывает **реализованные возможности** приложения (не отдельные коммиты). Структура разбита по доменным областям и ролям. Исходный код: **`apps/web`**.

---

## 1. Аутентификация и профиль

| Возможность | Где в UI / API |
|-------------|----------------|
| Вход по email и паролю | `/auth/login`, `POST /api/auth/login` |
| Выход | `POST /api/auth/logout` |
| Текущий пользователь | `GET /api/auth/me` |
| Смена пароля (обязательная после сброса и т.п.) | `/dashboard/change-password`, `POST /api/auth/change-password` |
| Общий профиль | `/dashboard/profile`, `GET/PATCH /api/profile` |
| Профиль студента | `/dashboard/student/profile`, API `student/profile` |
| Профиль учителя | `/dashboard/teacher/profile` |
| Предпочтения (тёмная тема и др.) | `GET/PATCH /api/preferences`; тема сохраняется и подтягивается в оболочке дашборда |

Сессия: **JWT** в httpOnly cookie; защита `/dashboard` через **`middleware.ts`**.

---

## 2. Студент (`STUDENT`)

### Академические данные

- **Дашборд** — `/dashboard/student`.
- **Расписание** — `/dashboard/student/schedule`; данные через API расписания (серверный/клиентский доступ к занятостям по роли).
- **Оценки** — список и детали; API: `grades`, `student/grades`, статистика и экспорт где предусмотрено (`grades/stats`, `grades/export`).
- **Журнал (gradebook)** — `/dashboard/student/gradebook`.
- **Посещаемость** — просмотр своей посещаемости; API `student/attendance`.

### Кампус и жизнь школы

- **Новости университета** — `/dashboard/student/news`; контент админский; API `university-news`.
- **Объявления** — `/dashboard/student/announcements`; фильтрация видимости; отметка прочитанных — `announcements/read`, счётчик непрочитанных в сайдбаре.
- **Новости студсовета** — `/dashboard/student/council-news`; API `council-news`.
- **События** — календарь событий, регистрация на событие; API `events`, `student/events/[id]/register`.
- **Спортивные секции / клуб** — расписание секций, регистрация; API `sports`, `student/sports/[id]/register`.
- **Столовая** — `/dashboard/student/canteen`: просмотр меню **по выбранной календарной дате**, категории блюд (завтрак, обед, перекусы, напитки), цена, калории, наличие. Данные: `GET /api/canteen/menu?date=YYYY-MM-DD`.
- **Преподаватели** — `/dashboard/student/teachers`; API `teachers`.
- **Портфолио** — биография и достижения студента (модели `Portfolio`, `PortfolioAchievement`).
- **Рейтинги / академический рейтинг** — `/dashboard/student/rankings`; данные `AcademicRanking`, API `rankings`.

### Сервисы

- **Запросы документов** — подача заявок студентом; API `student/document-requests`, вложения и выдача файлов через `document-requests/attachments/...`.
- **Уведомления** — список, отметка прочитанным, «прочитать всё»; API `notifications`, `notifications/[id]/read`, `notifications/read-all`.
- **Lost & Found** — просмотр и участие в объявлениях о находках/потерях; API `lost-found`.
- **Бюллетень** — объявления частных продаж/услуг; модель `BulletinPost`, API `bulletin`.

## 3. Учитель (`TEACHER`)

- **Дашборд** — `/dashboard/teacher`.
- **Расписание** — `/dashboard/teacher/schedule`; API `schedule`.
- **Посещаемость** — учёт по занятиям и классам: страницы `teacher/attendance`, отметки по ячейкам, обзоры; API `teacher/attendance`, `teacher/attendance/cell`, `teacher/attendance/session`, `teacher/attendance/overview`, а также маршруты с `[id]` для конкретных сессий.
- **Мои классы** — состав студентов; API `teacher/my-classes`, `teacher/my-classes/[id]/students`.
- **Оценки** — выставление и управление; API `grades`, `grades/[id]`.
- **Объявления** — создание/просмотр в рамках прав; API `announcements`.
- **Документы** — запросы справок и т.д. для сотрудников (`DocumentType` включает типы для учителя); UI `teacher/documents`.
- **Уведомления** — как у других ролей.
- **Lost & Found** — участие в модерации/просмотре по политике UI.
- **Столовая** — `/dashboard/teacher/canteen`: **только просмотр меню**, как у студента (общий компонент страницы); редактирование меню недоступно из этой роли.

## 4. Администратор (`ADMIN`)

### Управление пользователями и доступом

- Пользователи: список, создание, редактирование, **блокировка**, **сброс пароля** — API `admin/users`, `admin/users/[id]`, `admin/users/[id]/block`, `admin/users/[id]/reset-password`.
- Системный **замок** приложения для не-админов — `admin/system-lock` (в связке с проверками в `getApiSession`).

### Учебный процесс

- **Классы** — CRUD, привязка студентов и учителей — `admin/classes`, `admin/classes/[id]`, вложенные маршруты для студентов и учителей класса.
- **Расписание** — админское расписание с возможными подтверждениями конфликтов — `admin/schedule`, `admin/schedule/[id]` (в т.ч. логика подтверждения переопределений при необходимости).
- **Посещаемость** — обзор и правки на уровне админа — `admin/attendance`, `admin/attendance/overview`, `admin/attendance/cell`.
- **Рейтинги** — пересчёт — `admin/rankings/refresh`.

### Контент и коммуникации

- **Новости университета** — управление материалами (`university-news/[id]`).
- **Объявления** — массовые/таргетированные объявления с аудиторией по классу/роли.
- **Уведомления** — массовые уведомления пользователям (раздел админских уведомлений).

### Прочее

- **Запросы документов** — очередь заявок, статусы, заметки администратора — `admin/document-requests`.
- **Lost & Found** — модерация записей.
- **Столовая** — пункт меню `/dashboard/admin/canteen`: **просмотр меню для кампуса** (аналог студенческого). Редактирование меню и позиций выполняется через API с ролями **`CANTEEN_STAFF`** и **`ADMIN`** (`POST/PATCH` к ресурсам меню).

---

## 5. Персонал столовой (`CANTEEN_STAFF`)

- **Дашборд столовой** — `/dashboard/canteen`: краткий обзор (меню на сегодня при наличии записи в БД).
- **Менеджер меню** — `/dashboard/canteen/menu`: создание меню на дату, добавление позиций по категориям, калории, цены, доступность; копирование меню с другой даты (API `canteen/menu/[id]/copy-from`).
- **Документы** — типы запросов, связанные с оформлением работы в столовой (`DocumentType`).
- **Уведомления**, **Lost & Found** — как у других ролей по конфигурации сайдбара.

---

## 6. Общие разделы дашборда

Страницы без префикса роли там, где они универсальны:

- Смена пароля, профиль (см. §1).
- Отдельные общие страницы новостей/спорта могут дублироваться по ссылкам из сайдбара разных ролей — см. дерево **`apps/web/src/app/dashboard`**.

## 7. API — обзор по группам

Ниже не перечислены все query-параметры и тела запросов — см. конкретные **`route.ts`** при интеграции.

| Группа | Назначение |
|--------|------------|
| `auth/*` | вход, выход, сессия, смена пароля |
| `admin/users`, `admin/classes`, `admin/schedule`, `admin/attendance`, `admin/document-requests`, `admin/rankings`, `admin/system-lock` | администрирование |
| `teacher/attendance`, `teacher/my-classes`, `grades` | учитель и оценки |
| `student/*` | профиль студента, расписание студента, оценки студента, регистрации |
| `schedule`, `grades`, `grades/export`, `grades/stats` | расписание и оценки (общая логика по роли) |
| `announcements`, `announcements/read`, `announcements/[id]` | объявления |
| `events`, `student/events` | события |
| `university-news`, `council-news` | новости |
| `sports` | спортивные секции |
| `canteen/menu`, `canteen/menu/[id]/items`, `itemId`, `copy-from` | меню столовой |
| `document-requests`, вложения | документы и файлы |
| `lost-found`, `lost-found/[id]` | находки |
| `bulletin` | бюллетень |
| `notifications/*` | уведомления |
| `preferences` | пользовательские настройки |
| `rankings` | рейтинги |
| `attendance/analytics` | аналитика посещаемости (где разрешено ролью) |
| `students`, `teachers` | справочные списки для UI |

Ответы успешных запросов в формате **`{ "data": ... }`**, ошибок **`{ "error": "..." }`** (см. `apps/web/src/lib/api-response.ts`).

## 8. Особенности доменной логики

### Объявления и видимость

Видимость объявлений зависит от роли, класса и прочих правил — сбор условий в **`buildAnnouncementWhereForUser`** (`apps/web/src/lib/announcement-visibility.ts`).

### Посещаемость

Отметки привязаны к **`ScheduleItem`**, студенту, дате (`Attendance` с уникальным ключом на комбинацию студент–слот–день).

### Столовая и даты

Для параметра **`date=YYYY-MM-DD`** при работе с полем PostgreSQL **`@db.Date`** используется разбор **`parseIsoDateUtcCalendar`**, чтобы календарный день в запросе совпадал с записью в БД независимо от часового пояса сервера.

### Блокировки

Неактивные пользователи, блокировка по времени и системный замок отсекаются в **`getApiSession`** — для таких сессий API возвращает отказ в доступе.

## 9. Заметные доработки (эволюция продукта)

Фиксируются здесь **для истории**, без привязки к номерам версий:

1. **Столовая для всех ролей кампуса** — студенты, учителя и администраторы используют **единый экран просмотра меню** (страница студента + реэкспорт для teacher/admin). Редактирование меню остаётся у **персонала столовой** и **администратора** через Menu Manager и соответствующие API.
2. **Интерфейс меню столовой** — выбор даты, вкладки категорий, карточки блюд, индикаторы наличия, обработка ошибок загрузки (в т.ч. неавторизованный доступ).
3. **Исправление загрузки меню по дате** — корректный разбор строки даты для API меню (см. §8 «Столовая и даты»).

При расширении функциональности имеет смысл дополнять этот раздел краткими пунктами «что изменилось».

## 10. Тестовые данные

Скрипт **`npm run db:seed`** (`apps/web/prisma/seed.ts`) создаёт пользователей по ролям, классы, расписание, оценки, события, **меню столовой на сегодня и завтра**, заявки документов и др.

Учётные записи для ручной проверки описаны в **`TEST_CREDENTIALS.md`** в корне репозитория.
